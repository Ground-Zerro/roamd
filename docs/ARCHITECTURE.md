# Устройство демона

> Документация для версии **roamd 1.0.1-r25** (веб-интерфейс **luci-app-roamd 1.0.1-r7**).

Реализация `roamd`: модули, работа с hostapd, ubus-интерфейс, скрипты и данные. Правила
принятия решений описаны в [HOW_IT_WORKS.md](HOW_IT_WORKS.md), Mesh Wi-Fi-система — в
[MESH.md](MESH.md), опции — в [CONFIGURATION.md](CONFIGURATION.md).

## Общая схема

```
                 ubus
  ┌──────────────────────────────┐
  │  hostapd.<интерфейс> (2.4)   │◀── события probe / auth / assoc / disassoc,
  │  hostapd.<интерфейс> (5)     │    beacon-report
  └──────────────────────────────┘
        ▲                  │
        │ вызовы           │ события
        │                  ▼
  ┌──────────────────────────────┐        ┌────────────────────────┐
  │            roamd             │───────▶│ /etc/config/wireless   │
  │  bss ─ sta ─ policy ─ pair   │ libuci │ /etc/config/roamd      │
  │  provision ─ mesh_*          │        └───────────┬────────────┘
  └──────────────────────────────┘                    │ network reload
        │           │                                 ▼
        │ ubus      │ uloop_process               netifd → hostapd
        │ "roamd"   ▼
        │     /usr/libexec/roamd/*.sh  ── SSH / HTTPS ──▶ узлы mesh
        ▼
  luci-app-roamd
```

Демон — однопоточный цикл событий `uloop`. Всё, что длится долго или требует внешних утилит
(SSH, `curl`, пакетные менеджеры), вынесено в shell-скрипты, которые демон запускает как
дочерние процессы и отслеживает через `uloop_process`.

## Модули

| Файл | Ответственность |
|---|---|
| `main.c` | Запуск, автопереподключение к ubus, цикл `uloop`; подкоманды `apk-index` и `apk-block` выполняются без запуска демона |
| `config.c` | Чтение `/etc/config/roamd` по таблице опций `opts[]`, умолчания, санитизация; дамп действующей конфигурации; правила устройств (AVL по MAC: разрешённый диапазон и список узлов); объект `uci_session` — единственный путь чтения и записи UCI для всех модулей, `commit` только при изменениях |
| `bss.c` | Обнаружение объектов `hostapd.*` и подписка на них, разбор событий, опрос; синхронизация Neighbor Report |
| `sta.c` | Таблица клиентов (AVL по MAC), состояние по каждому диапазону, события подключения и смены точки, защита от «метаний» после перевода |
| `policy.c` | Решения: пускать ли на диапазон, кого и куда переводить; Beacon Request, BTM, принудительное отключение |
| `pair.c` | Проверка, что точки разных диапазонов с одним SSID действительно образуют пару для роуминга |
| `provision.c` | Запись 802.11k/v/r в `/etc/config/wireless`; mobility domain; обмен ключами FT для WPA3 и WPA-Enterprise |
| `mesh.c` | Роль и секция `mesh`, члены системы, запуск фоновых задач, карта точек, радио-данные клиентов из `iwinfo`, хранилище межузловых соседей, подготовка зависимостей |
| `mesh_ctrl.c` | Контроллер: задачи поиска, захвата, обновления и освобождения, опрос членов, транспортная сеть, STP мостов, синхронизация, таймер автообновления |
| `mesh_node.c` | Узел: применение профиля, отчёт, диагностика; сторож узла — контакт по ICMP, события звена, выбор родителя, транспортная станция, ретрансляция транспорта; индикатор связи, межузловой перевод и удаление станции |
| `mesh_bridge.c` | Разбор мостов через sysfs: порты, таблица MAC-адресов, порт родителя, проводные клиенты, член системы за портом; стоимость STP беспроводных портов, корень STP, carrier порта, состояние станции |
| `mesh_clients.c` | Реестр клиентов всей системы, сохранение в `/tmp/roamd`, правка правил клиента |
| `mesh_log.c` | Кольцевой журнал переходов, сохранение, приём событий узлов с отсевом повторов |
| `ubus_api.c` | Объект ubus `roamd`, разбор аргументов и проверка роли |
| `apk.c` | Разбор индексов и пакетов apk v3: ADB-контейнер и собственный распаковщик DEFLATE по RFC 1951 |

## Запуск и остановка

1. `main()` обрабатывает подкоманды `roamd apk-index <packages.adb>` (печатает
   `имя версия размер хеш`) и `roamd apk-block <пакет.apk>` (отдаёт первый ADB-блок, чей SHA256
   указан в индексе).
2. Загружается конфигурация. При `enabled=0` процесс завершается.
3. После подключения к ubus регистрируется объект `roamd`, находятся точки hostapd,
   выполняется автонастройка Wi-Fi и запускается mesh-часть (`mesh_start()`).
4. При остановке журнал переходов и реестр клиентов сбрасываются на диск.

Init-скрипт запускает демон под procd с `respawn` и регистрирует `procd_add_reload_trigger`
на конфигурации `roamd` и `wireless`. `reload` вызывает `ubus call roamd reload`: конфигурация
перечитывается без перезапуска процесса и без разрыва соединений.

## Работа с hostapd

### Обнаружение точек

При старте — `ubus_lookup("hostapd.*")`, далее подписка на событие `ubus.object.add`:
появление и исчезновение интерфейсов (например, после `wifi reload`) обрабатывается на лету.

Для каждого BSS отправляются:

* `notify_response {notify_response: 1}` — hostapd ждёт ответа демона на события
  `probe`/`auth`/`assoc` и использует возвращённый код как статус кадра;
* `bss_mgmt_enable {neighbor_report, beacon_report, bss_transition}`.

Если hostapd не ответил вовремя (так бывает сразу после загрузки), включение повторяется в
каждом цикле опроса, пока не пройдёт.

### Цикл опроса

Каждые `poll_interval` (2 с) для каждого BSS:

1. `get_status` — SSID, BSSID, частота, канал, класс операций, состояние.
2. Для управляемых BSS — `get_clients`: подключённые, их сигнал, HT, поддержка Beacon Report
   (`rrm`) и BSS Transition (бит 19 `extended_capabilities`).
3. `rrm_nr_get_own` — собственный Neighbor Report, пока он не получен.
4. `rrm_nr_set` — точкам с тем же SSID передаются Neighbor Report соседей (локальных и
   точек Mesh Wi-Fi-системы), не больше 8. Список отправляется при изменении отпечатка и не
   реже раза в минуту.
5. Прогон политики.
6. Удаление записей клиентов старше `age_time`.

Вызовы синхронные с таймаутом 500 мс: локальных BSS немного, а код без конечного автомата
на асинхронных запросах заметно проще.

### Источники данных о сигнале

| Источник | Что даёт |
|---|---|
| События `probe` / `auth` / `assoc` | RSSI в том диапазоне, где клиент подал кадр |
| `get_clients` → `signal` | RSSI подключённого клиента в текущем диапазоне |
| `beacon-report` | RSSI другого диапазона, измеренный клиентом: `rcpi / 2 − 110`, RCPI от 200 отбрасывается |
| Поправка `cross_band_delta` | оценка другого диапазона, когда измерений нет |

### Точки входа политики

`roam_policy_allow()` вызывается из обработчика `probe`/`auth`/`assoc`. Возврат `false`
заставляет hostapd ответить кодом 17. Первая проверка — `roam_device_node_allowed()`
(разрешён ли клиент на этом устройстве), затем `roam_device_lock()` (разрешённый диапазон),
затем пороговая логика.

`roam_policy_run()` вызывается из цикла опроса для каждого BSS: отключает клиентов, которым
устройство не разрешено, запрашивает Beacon Report при нехватке данных и принимает решение о
переводе в `sta_should_leave()`. Число и частоту запросов ограничивает
`roam_policy_can_steer()` — та же проверка стоит в межузловом `mesh_node_steer()`.

Перевод — `bss_transition_request` с Neighbor Report цели и флагом `abridged`, без
`disassociation_imminent`. Клиента без 802.11v при `allow_kick=1` отключает `del_client` с
`ban_time = deny_time`.

**Параметры `bss_transition_request`.** hostapd читает `mbo_reason`, `cell_pref` и
`reassoc_delay` из неинициализированных переменных, если их не передать, и отвечает
`Invalid argument`. Демон всегда передаёт все три поля явно; `reassoc_delay` обязан быть нулём
без `disassociation_imminent`.

## Автонастройка беспроводной сети

`roam_wireless_apply()` проходит по включённым секциям `wifi-iface` в режиме `ap` (с учётом
фильтра `ssid`) и приводит опции к состоянию, заданному в `/etc/config/roamd`:

| Опция `wireless` | Значение |
|---|---|
| `ieee80211k`, `rrm_neighbor_report`, `rrm_beacon_report` | `neighbor_reports` |
| `bss_transition`, `wnm_sleep_mode` | `bss_transition` |
| `ieee80211r` | `fast_transition` и шифрование семейства WPA2/WPA3 (`psk2`, `psk-mixed`, `sae*`, `wpa2*`, `wpa3*`, `wpa-mixed*`) |
| `ft_over_ds` | `ft_over_ds` при включённом FT |
| `ft_psk_generate_local` | `1` для WPA2 с общим паролем (`psk*`), `0` для WPA3 и WPA-Enterprise |
| `mobility_domain` | заданный `mobility_domain` или хеш FNV-1a от SSID, свёрнутый до 16 бит |
| `nasid`, `pmk_r1_push`, `r0kh`, `r1kh` | WPA3 и WPA-Enterprise: идентификатор устройства, `0`, универсальные ключи обмена с `mesh.ft_key` |

Запись и `network reload` выполняются только если хотя бы одно значение изменилось. Кроме
запуска и `reload`, функция вызывается через 2 секунды после появления нового BSS: сеть,
созданную мастером LuCI или вручную, демон дооснащает без перезапуска, а повторный проход не
находит отличий и не зацикливается.

## Проверка пары

`roam_pair_evaluate()` вызывается из метода `status` и для каждого BSS выставляет битовую
маску причин. Живая часть берётся из состояния демона (есть ли парная точка, управляется ли
BSS, получен ли Neighbor Report), конфигурационная — из `/etc/config/wireless`: все `ap`-секции
с тем же SSID сравниваются между собой. Группировка идёт по SSID — ровно по тому признаку,
по которому клиент считает точки одной сетью.

| Код | Смысл | Уровень |
|---|---|---|
| `not_managed` | BSS не управляется службой | роуминга нет |
| `no_peer` | нет точки другого диапазона с этим SSID | роуминга нет |
| `disabled` | одна из точек выключена | роуминга нет |
| `encryption` | разные типы шифрования | роуминга нет |
| `key` | разные пароли | роуминга нет |
| `network` | точки в разных сетях (мостах) | роуминга нет |
| `no_11k` | 802.11k выключен | не в полную силу |
| `no_11v` | 802.11v выключен | не в полную силу |
| `fast_transition` | 802.11r или mobility domain настроены несогласованно | не в полную силу |
| `no_neighbor_report` | точки ещё не обменялись Neighbor Report | не в полную силу |

В `status` это отдаётся как `state` (`ok`, `degraded`, `broken`) и список кодов, которые
LuCI переводит на язык интерфейса.

## ubus-интерфейс

Объект `roamd`. Колонка «Доступ» показывает, через какой ACL метод доступен снаружи:
**LuCI** — `luci-app-roamd.json` (чтение или запись), **канал** — группа `roamd` для входа
контроллера на узел. Методы без отметки вызываются только локально с правами root.

| Метод | Аргументы | Роль | Доступ | Назначение |
|---|---|---|---|---|
| `status` | — | обе | LuCI, канал | включённые механизмы, роль, точки доступа с состоянием пары и клиентами |
| `config` | — | обе | — | действующая конфигурация: все опции `opts[]` с учётом умолчаний |
| `reload` | — | обе | LuCI, канал | перечитать конфигурацию, дооснастить Wi-Fi, перезапустить mesh-часть, раскатать профиль |
| `mesh_role` | — | обе | LuCI, канал | роль, флаг `enabled`, `member_id` |
| `mesh_status` | — | обе | LuCI, канал | контроллер: счётчики, сам контроллер, члены с живым состоянием, настройки MESH, текущая задача, точки `self_aps`, готовность зависимостей. Узел: контроллер и возраст контакта, настройки |
| `mesh_clients` | — | обе | LuCI | реестр клиентов |
| `mesh_log` | — | обе | LuCI | журнал переходов |
| `mesh_discover` | `start?`, `stop?` | контроллер | LuCI | поиск кандидатов: запуск, остановка, состояние и результат |
| `mesh_acquire` | `addr` | контроллер | LuCI | запуск захвата, возвращает `task_id` |

| `mesh_update` | `id` | контроллер | LuCI | обновление пакетов на узле |
| `mesh_self_check` | `start?`, `stop?` | контроллер | LuCI | проверка обновлений контроллера |
| `mesh_self_update` | — | контроллер | LuCI | обновление пакетов контроллера |

| `mesh_client_forget` | `mac` | контроллер | LuCI | удалить клиента из реестра и его правила |
| `mesh_settings` | `backhaul_enabled?`, `backhaul_ssid?`, `backhaul_key?`, `wifi_shutdown?`, `backhaul_delta?`, `backhaul_min_signal?`, `auto_update?`, `auto_update_every?`, `auto_update_unit?`, `pkg_url?`, `controller_name?` | контроллер | LuCI | запись секции `mesh`, перестройка транспорта, таймера и раскатка |
| `mesh_log_ingest` | `id`, `node`, `events` | контроллер | — | приём событий узла из периодического прохода |
| `mesh_apply` | профиль | обе | канал | применить профиль контроллера |
| `mesh_report` | — | обе | канал | живое состояние устройства (раздел ниже) |
| `mesh_diag` | — | обе | канал | снимок для разбора неполадок без SSH: версии, конфигурации, адреса, мост, сервисы, объекты hostapd, хвосты журналов |
| `mesh_steer` | `mac`, `neighbors?` | обе | канал | запрос 802.11v клиенту с переданными кандидатами |

Методы, меняющие состав системы и правила, при роли `node` отвечают `Permission denied`.

### Отчёт устройства

`mesh_report` содержит: роль, `member_id`, `controller_id`, версию ОС, архитектуру, версии
пакетов `roamd` и `luci-app-roamd`, время работы; `clients[]` (MAC, диапазон, сигнал,
скорость, стандарт, ширина, потоки, шифрование, трафик, время ассоциации, признак `wired`);
`heard[]` (необслуживаемые станции со свежим сигналом); `connection`, `uplink_band`, `via`;
применённый профиль `profile`; точки `aps[]` с hex-элементом Neighbor Report; последние 100
событий журнала.
